## 实验的目的

验证同一常驻模型能保留低频 query，同时以当前视觉输入生成较高频轨迹，且独立控制循环不被模型阻塞。
可证伪条件：query 实际更新数少于轨迹数、存在复用、年龄不超过 0.5 秒、完成输出均为有限 [32,3]，控制循环事件独立产生。
不把平均频率视为每个周期截止时间通过，不把记录输入 shadow 视为真实采集或实车验收。

## 实验的 setting

### 数据

复用同一已保存 clip，五帧 FPV 5 Hz，历史 BEV 2 Hz。重新组织动作请求为 5 Hz；
输入不足五帧的预热时段保留在源时间轴内。不重复旧 2 Hz age=0 验收。
BEV 不是高德截图，非零 query age 的语义可靠性尚未验收。

### 算法和改动

模型源码不改。query_cache_max_age_sec 从 0 改为 0.5，query_refresh_period_sec 保持 0.5。
客户端使用独立 20 Hz 控制时钟和已有单个待处理输入队列；回放延迟时只提交最新到期输入，保留跳过计数。
query 刷新按已接收观测的源年龄触发，因此在 0.2 秒网格上不是严格 2 Hz；报告实测值。

### 训练与评测配置

无训练。固定同一模型和 engine，bf16、SDPA、图像预算 128、flow_steps=8、noise_scale=0、seed=20260823。
GPU6 启动前须空闲，已有 GPU5 服务保持。一次完整记录区间，无推理重试、无额外暖机请求。
模型冷启动请求计入，避免把暖态数字表述为整段实时表现。计划最大年龄 0.75 秒，shadow 仅记录候选。

### 对照组与不变量

沿用旧服务代码、模型、engine、缓存容量与数据。不重跑对照组；本次只验证未覆盖的 query 保留与控制循环组合。
频率 `(N-1)/(t_last-t_first)` 在各自时钟域计算，另报告最大间隔和全部跳过/丢弃数。

### 可视化与导出计划

启动、运行失败和丢弃记录全部保留，不通过重试掩盖。

## 分析实验结果，可能的原因

预期较慢的 query 更新允许多数动作窗口复用语言结果；真实吞吐仍受新视觉、TRT、传输和同步影响。
若冷启动导致跳过输入，应与稳定阶段分别解释，但整段结果保留该成本。
本次证据支持工程假设：181 次复用、不同更新率和控制循环同时成立。query 刷新原因是 initial 1 次、expired 92 次，
没有 instruction/route/scene 变化，不能把本次结果当作这些条件的在线触发验收。
起步期丢弃和过期由日志时序定位；首请求内部初始化的具体算子原因未做额外性能剖析。
