# UrbanNav Stage I SFT Projection Contract

RouteServer owns the canonical Stage I exchange view. It does not change the
Reasoning V4.6 or VQA V2.0 annotations and does not create new teacher labels.

The implementation in `src/mcp_server/contracts/stage_i_sft.py` defines three
immutable discriminated views: `full_cot`, `vqa`, and `decision`. The projector
in `src/mcp_server/data/stage_i_views.py` derives them only from formal
Reasoning V4.6 training views or accepted VQA V2 annotations.

Core guarantees:

- current FPV is mandatory and distinct from `fpv.history_*`;
- selected instruction must have an exact source-revision
  `StageIInstructionProvenanceV1` record with `training_role=primary`;
- goal image, pixel goal, and waypoint remain disabled in v1;
- FullCoT is not regenerated after modality dropout;
- VQA retains every required modality and annotation evidence ref;
- Decision-only contains no FullCoT prefix and requires visible authority or
  an explicit dataset FPV behavior-cloning capability;
- trajectory/System1 sidecars never enter the exchange contract;
- character loss spans partition the exact assistant target;
- parent identities and the projection digest make every view auditable.

Expected rejections are represented by the separate
`StageIProjectionDropV1` audit contract. The `*_with_audit_v1` projection
entry points return this record with a bounded reason code and immutable digest;
drop audits are never part of the training-view union.

The contract artifacts under `schemas/stage_i_sft/` are generated by
`tools/model_processing/export_stage_i_sft_contract_artifacts.py` and exported
byte-for-byte into the standalone `UrbanNav-Contracts` package by
`sync_stage_i_sft_cross_repo.py`. ms-swift keeps a compatibility alias that
imports this package; it does not own a second Stage I implementation.

## Private direction geometry sidecar

`full_cot`、`decision` 和 V2 reasoning-dropout view 可携带可选
`DirectionGeometrySupervisionV1`。它必须逐字段匹配对应的 strong
`DirectionSupervisionV4`，但只作为 physical manifest 的 sampler/evaluator metadata：

```text
direction_raw_angle_deg
direction_boundary_distance_deg
direction_geometry_confidence
direction_angle_valid
direction_stop_rule_verified
```

该 metadata 不参与 user/system message 构造、不进入 assistant text，也不改变当前 Stage I
LM loss。ms-swift 只能利用它做类内 sampling priority 与 offline geometry metrics；缺失 sidecar
必须保持 `unavailable`，禁止回退为离散候选中心。

## V3 reasoning-dropout ownership

RouteServer owns one pure V2 canonical projection:

```text
StageIFullCoTViewV2 -> project_reasoning_dropout_from_full_v2 -> <Decision>
```

It proves that a no-CoT target is the exact `<Decision>` projection of a
validated FullCoT parent. It does **not** choose whether the projection is a
training example, does not materialize a V3 mirror manifest, and does not
change model-visible images, instruction, evidence, or direction provenance.

ms-swift owns the V3 epoch routing decision. For every sampled parent it emits
one route receipt, `full_cot` or `no_cot`; the same parent may not enter both
routes in one immutable epoch. This separation keeps annotation canonical while
making sampling, active-token accounting, and route-capacity failures explicit
training concerns. Historical V2 static `reasoning_dropout` artifacts remain
readable for audit only and are forbidden V3 compiler inputs.

## Canonical migration and batch entry points

Legacy artifacts are never edited in place:

- `migrate_reasoning_v4_annotations.py` accepts already-structured V4.6 rows,
  normalizes only the frozen Scene/Constraint aliases, rebuilds the matching
  candidate grounding sections and Action Reconciliation audit, and reports
  formal eligibility. Human adjudication is not transferred to a changed
  `audit_id`.
- `migrate_vqa_v2_artifacts.py` replaces the retired
  `direction_output_space` with the canonical `direction_context`, then
  recomputes source fingerprints, annotation identities, and context digests.
  It rebuilds E0 `derived_gt` questions with minimal evidence and verifies the
  answer is unchanged. Existing `lvlm_weak` answers retain their original
  evidence and are reported as requiring re-annotation before reduced-modality
  use.
- New VQA questions use task-required minimal evidence. The weak-label teacher
  receives only those evidence records and attached images. This is a prompt
  policy v2.1 change and does not retroactively bless old weak labels.

`build_stage_i_instruction_provenance.py` turns explicit, exact-source
assignments into the digest-bound provenance registry. Its policy mode reads
`config/stage_i_sft/instruction_policy_v1.json`, matches the SHA-256 of the
exact visible text, and fails closed on every instruction not listed in that
frozen policy. The current policy classifies the two frozen Foxglove/SideWalk
task-contract strings as `primary` because they occur verbatim in the student
prompt; it does not infer roles from dataset names. `project_stage_i_batch.py`
is the production batch entry:
it requires that registry, emits both exchange views and structured drops, and
fails closed when a present instruction has no matching fingerprint/text
record. The low-level projector's role argument remains available for unit
tests and controlled composition, but must not be used as a production default.
